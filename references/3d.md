# Deterministic 3D Video Reference Guide

Use this guide whenever a prompt calls for **3D scenes, product turntables, isometric SaaS mockups in 3D space, volumetric data, shaders, or photorealistic PBR renders** at up to **4K (3840×2160 / 2160×3840) @ 60fps**.

> **Golden Rule of Programmatic 3D:** **NEVER** drive motion with wall-clock timers (`useFrame((_, delta) => ...)` incrementing mutable state or `requestAnimationFrame`). Every pixel at frame `f` (or time `t`) must be a **pure deterministic function** of `useCurrentFrame()` / `t` so parallel headless render workers produce zero frame tearing or jitter.

---

## Engine Selection for 3D

| Need | Engine | Why |
| :--- | :--- | :--- |
| React UI overlays + 3D canvas / WebGL product showcase | **Remotion + `@remotion/three`** | Seamless `<ThreeCanvas>` mixed with `<Sequence>` HTML HUD/captions. |
| Pure WebGL shaders / particle fields / GLSL (native Canvas) | **Three.js + `window.kinearc.seek(t)` / `renderAt(t)`** | Zero React reconciler overhead; deterministic `?t=` & `?scale=2` browser/WebCodecs 4K export via `kinearc_cli.py` + `engine/render.mjs`. |
| 3D mathematical surfaces, vectors, axes, geometry proofs | **Manim `ThreeDScene`** | Native Python parametric surfaces + 3D camera + crisp LaTeX (`-qk` for 4K60). |
| Photorealistic PBR glass, fluids, raytraced shadows, `.glb` shots | **Blender Headless Python (`blender -b -P`)** | Cycles/EEVEE raytracing -> PNG/RGBA plates composited in Remotion or FFmpeg. |

## 1. Remotion + `@remotion/three` (React Three Fiber)

### Installation
```bash
npm install three @types/three @react-three/fiber @remotion/three
```
*(Match `@react-three/fiber` major version to your React major version, e.g. v8 for React 18, v9 for React 19).*

### Deterministic `<ThreeCanvas>` Pattern (`useCurrentFrame()` only)
```tsx
import React from 'react';
import { ThreeCanvas } from '@remotion/three';
import { interpolate, spring, useCurrentFrame, useVideoConfig } from 'remotion';

const HeroBox: React.FC = () => {
  const frame = useCurrentFrame();
  const { fps } = useVideoConfig();

  const enter = spring({ frame, fps, config: { damping: 14, stiffness: 120 } });
  const rotY = interpolate(frame, [0, 180], [0, Math.PI * 2]);
  const floatY = Math.sin(frame / 18) * 0.12;

  return (
    <mesh rotation={[0.35, rotY, 0]} position={[0, floatY, 0]} scale={enter} castShadow>
      <boxGeometry args={[1.6, 1.6, 1.6]} />
      <meshStandardMaterial color="#6366f1" metalness={0.35} roughness={0.22} />
    </mesh>
  );
};

export const Scene3D: React.FC = () => {
  const { width, height } = useVideoConfig();
  return (
    <ThreeCanvas
      width={width}
      height={height}
      shadows
      camera={{ position: [0, 1.2, 5], fov: 38 }}
      style={{ backgroundColor: '#09090b' }}
    >
      <ambientLight intensity={0.45} />
      <directionalLight position={[4, 6, 4]} intensity={2.2} castShadow />
      <HeroBox />
    </ThreeCanvas>
  );
};
```

### Headless WebGL & 4K Rendering Flags for Remotion
In Docker, CI, or headless Windows/Linux servers, pass a Chromium GL backend explicitly when rendering `<ThreeCanvas>`:
```bash
# Hardware/ANGLE GPU acceleration (fast on local desktop/Windows/macOS)
npx remotion render src/index.ts Scene3D out_4k.mp4 --gl=angle --scale=2

# Pure CPU fallback (reliable on headless servers without GPU drivers)
npx remotion render src/index.ts Scene3D out_4k.mp4 --gl=swiftshader --scale=2
```
* **4K Tip:** Design your camera/HUD layout at `1920×1080` (or `1080×1920`) and pass `--scale=2` to render sharp **3840×2160 / 2160×3840** WebGL geometry without multiplying HUD font sizes by 2.
* Keep `useVideoConfig().width` and `height` passed explicitly to `<ThreeCanvas width={width} height={height}>`.

## 2. Standalone Three.js + WebGL (`window.kinearc.seek(t)` / `renderAt(t)`)

When building high-speed shader art, 3D data particles, or non-React 3D scenes for interactive web deployment or `kinearc`'s native HTML/Canvas WebCodecs 4K engine (`scripts/kinearc_cli.py`, `engine/render.mjs`, `references/kinearc-engine.md`, and `references/web-interactive.md`):
* Replace `<canvas>` 2D context with `THREE.WebGLRenderer({ canvas, antialias: true, preserveDrawingBuffer: true })`.
* Parse `?t=` and `?scale=` from `URLSearchParams(location.search)`, call `renderer.setSize(W, H, false)` and `renderer.setPixelRatio(S)` where `const rawScale = parseFloat(q.get('scale') || ''); const S = Number.isFinite(rawScale) && rawScale > 0 ? rawScale : 1;` (`?scale=2` targets native 4K). Similarly guard `?t=` with `Number.isFinite(rawT) && rawT > 0 ? rawT : 0`.
* Expose `window.renderAt = (t) => { ... }` and `window.kinearc = { totalDuration, ready, seek: window.renderAt }`, computing camera matrix and mesh transforms directly from `t`, then finishing synchronously with `renderer.render(scene, camera)` so CDP/WebCodecs capture reads the completed frame immediately. Preview and render 4K directly inside `scripts/kinearc_ui.py` (`/api/render`) or via `python "<skill_dir>/scripts/kinearc_cli.py" render --project kinearc.project.json --out out_4k.mp4 --scale 2`.

## 3. Manim `ThreeDScene` (3D Math, Surfaces & Science)

Use Manim's native `ThreeDScene` when visualizing `R^3 -> R` surfaces, 3D vectors, orbits, or matrix transformations:

```python
from manim import *
import numpy as np

class ParametricWave3D(ThreeDScene):
    def construct(self):
        axes = ThreeDAxes(x_range=[-3, 3, 1], y_range=[-3, 3, 1], z_range=[-2, 2, 1])
        surface = Surface(
            lambda u, v: axes.c2p(u, v, 0.8 * np.sin(u) * np.cos(v)),
            u_range=[-3, 3], v_range=[-3, 3], resolution=(32, 32),
            fill_opacity=0.85, checkerboard_colors=[BLUE_D, BLUE_E]
        )
        self.set_camera_orientation(phi=68 * DEGREES, theta=-45 * DEGREES)
        self.add(axes)
        self.play(Create(surface), run_time=2.0)
        self.begin_ambient_camera_rotation(rate=0.25)
        self.wait(4.0)
        self.stop_ambient_camera_rotation()
```

Render natively at **4K 60fps** (`-qk`):
```bash
manim -qk --fps 60 scene.py ParametricWave3D
```

## 4. Blender Headless Python Pipeline (Photorealistic / `.glb` Renders)

When WebGL shading isn't photorealistic enough (glass refraction, caustics, complex imported CAD/`.glb` product rigs), author the scene in Python and invoke Blender headlessly (`blender -b -P render_scene.py`), then composite UI overlays in Remotion/FFmpeg:

```python
# render_scene.py — Run via: blender -b -P render_scene.py
import math, os
import bpy

bpy.ops.wm.read_factory_settings(use_empty=True)
scene = bpy.context.scene
scene.render.engine = 'BLENDER_EEVEE_NEXT'  # or 'CYCLES' with device='GPU'
scene.render.resolution_x = 3840
scene.render.resolution_y = 2160
scene.render.fps = 60
scene.frame_start = 1
scene.frame_end = 180
scene.render.film_transparent = True  # Transparent background for UI compositing!
scene.render.image_settings.file_format = 'PNG'
scene.render.image_settings.color_mode = 'RGBA'
scene.render.filepath = os.path.abspath("./frames/frame_")

# Camera rig
cam_data = bpy.data.cameras.new("Cam")
cam = bpy.data.objects.new("Cam", cam_data)
scene.collection.objects.link(cam)
scene.camera = cam

# Keyframe deterministic turntable orbit
for f in range(1, 181):
    angle = (f - 1) / 180.0 * math.tau
    cam.location = (6.0 * math.cos(angle), -6.0 * math.sin(angle), 2.2)
    direction = -cam.location
    cam.rotation_euler = direction.to_track_quat('-Z', 'Y').to_euler()
    cam.keyframe_insert(data_path="location", frame=f)
    cam.keyframe_insert(data_path="rotation_euler", frame=f)

bpy.ops.render.render(animation=True)
```
Then composite the transparent RGBA sequence over animated typography in Remotion (`<Img>` or FFmpeg `overlay`) so 3D photorealism meets crisp programmatic UI motion.
